# Руководство по внесению вклада в проект

Спасибо за желание помочь проекту — ваш вклад очень важен!

## Основные правила

Прежде чем начать, пожалуйста, ознакомьтесь с простыми правилами, которые помогут поддерживать качество и понятность изменений:

- Если вы собираетесь добавить **новую фичу** или внести серьёзные **архитектурные изменения**, сначала создайте [Issue](https://github.com/tuyuritio/astro-theme-thought-lite/issues) — так мы сможем обсудить идею и подобрать лучший план реализации.
- Один Pull Request должен решать **только одну задачу** или добавлять **одну функцию** — не объединяйте несколько несвязанных изменений в одном PR.
- Если необходимо рефакторить существующий код для поддержки новой функции — сделайте отдельный PR для рефакторинга до основного PR с фичей.
- Если PR добавляет новую функцию, опцию конфигурации или изменяет поведение, обновите документацию и примеры использования.
- Пожалуйста, запускайте базовые тесты и форматируйте код в соответствии с правилами проекта.

> [!Примечание]
> В проекте используется Biome как основной форматтер и линтер. Из‑за особенностей форматирования HTML‑похожего кода в Svelte и Astro файлах, для этих файлов используется Prettier как запасной инструмент.
> Сначала отформатируйте изменения через Prettier (для Svelte/Astro), затем примените Biome.

## Как отправить вклад

1. Форкните репозиторий в свой аккаунт: `Fork`.
2. Создайте новую ветку по шаблону: `git checkout -b feat/your-feature` (или `fix/..`, `docs/..` в зависимости от типа изменения).
3. Внесите изменения и зафиксируйте их локально — используйте правила коммитов (см. ниже):

	```bash
	git add .
	git commit -m "<type>(<scope>): краткое описание"
	```

4. Подтяните актуальные изменения из основной ветки, чтобы избежать конфликтов: `git pull origin main`.
5. Отправьте ветку в ваш форк: `git push origin feat/your-feature`.
6. Откройте Pull Request в основной репозиторий, подробно опишите цель PR и укажите связанные issue (если есть).

### Рекомендации по коммитам (Conventional Commits)

В проекте используется соглашение Conventional Commits — оно помогает автоматически генерировать changelog и поддерживать историю изменений понятной.

Формат:

```
<type>[(<scope>)]: <description>
```

Примеры типов (часто используемые):

- feat: новая функциональность
- fix: исправление бага
- docs: изменения в документации/контенте
- style: форматирование, исправления стиля (не меняют смысл кода)
- refactor: рефакторинг кода (без изменения функциональности)
- chore: вспомогательные задачи и обновления инфраструктуры

Рекомендуется добавлять scope, чтобы показать область изменений (например `i18n/ru` для русской локализации):

```
feat(i18n/ru): add Russian translations for content pages
docs(i18n/ru): translate documentation to Russian
```

В теле коммита можно кратко перечислить затронутые файлы и дать контекст (например, ссылку на Issue или причину изменения).
